The FCCM version of this work introduced an on-chip streaming dataflow for
MiniRocket, decomposing inference into three compute units---\texttt{load},
\texttt{feature\_extraction}, and \texttt{store}---connected by
\texttt{hls::stream} FIFOs over AXI-Stream interfaces and linked at build
time via the Vitis \texttt{sc=} directive. This decoupled HBM access from
compute and demonstrated that the inference pipeline could be expressed as
three independently synthesized kernels with bit-exact accuracy relative to
the monolithic variant.

For this work we extend the same on-chip streaming pattern to HYDRA, a
substantially more complex classifier with 512 learned convolutional kernels
and two pooling operations. The resulting \texttt{hydra\_stream} variant
(Table~\ref{tab:hydra_comparison}) preserves the three-kernel decomposition:
\texttt{load\_1} streams time series samples from HBM into an
\texttt{hls::stream<data\_t>} FIFO; \texttt{hydra\_inference\_1} consumes
from that FIFO through an AXI-Stream port, runs the full HYDRA pipeline
(convolution, dual soft/hard pooling, scaling, linear classification), and
emits a prediction into a second FIFO; \texttt{store\_1} drains that FIFO
back to HBM. Model state (\texttt{coefficients}, \texttt{kernel\_weights},
\texttt{biases}, \texttt{dilations}, \texttt{intercept}, \texttt{scaler\_mean},
\texttt{scaler\_scale}) remains on \texttt{m\_axi} ports since it is
per-model, not per-sample. The variant synthesizes at
\textbf{404.86\,MHz Fmax} (WNS \textbf{+0.375\,ns}) and matches the Python
reference classifier to within 0.00\% on InsectSound, MosquitoSound, and
FruitFlies, confirming that the on-chip streaming decomposition generalizes
to classifiers well beyond the MiniRocket feature extractor it was designed
around.

We note that the \texttt{hydra\_stream} variant is an architectural
demonstration, not a throughput optimization: the current host dispatches
kernels once per sample, so end-to-end throughput is dominated by OpenCL
command-queue overhead rather than kernel compute. For batch offline
inference the monolithic \texttt{hydra\_optimized\_v2\_fixed} variant
remains preferable; the streaming variant's value is in its composability
and its suitability for latency-sensitive or pipelined deployments where
samples arrive one at a time.
